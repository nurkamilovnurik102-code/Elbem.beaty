# Фото и галерея — что действительно работает

Firestore хранит **метаданные и URL фотографий**, но не заменяет хранилище файлов. В этом проекте нет платного Firebase Storage; на Firebase Spark нельзя рассчитывать на загрузку файлов в Cloud Storage.

## Загрузка с телефона или компьютера

На странице администратора теперь виден `<input type="file">` даже при подключённом Firebase. Поддерживаются JPEG/PNG/WebP/GIF/AVIF до 10 МБ. Без отдельного медиахостинга фото сохраняется в локальном IndexedDB браузера для предпросмотра. Такой адрес нельзя публиковать в Firestore: сохранение с локальным `elbem-local-image:` будет отклонено, чтобы не показывать чужим людям битые картинки.

## Чтобы новое фото было видно ВСЕМ

**Вариант 1 (самый простой):** загрузите фото на уже используемый Cloudinary через его панель, скопируйте публичную HTTPS-ссылку и вставьте её в поле изображения в админке, затем нажмите «Сохранить». При выполнении правил Firestore ссылка сохранится в существующей базе и обновится на других устройствах.

**Вариант 2 (прикрепить файл непосредственно из админки):** создайте в Cloudinary отдельный **unsigned** upload preset для изображений, ограничьте форматы (JPG, PNG, WebP и т. д.), папку, разрешение, следите за квотами. Добавьте в `.env.local` и Vercel Environment Variables:

```
VITE_CLOUDINARY_CLOUD_NAME=your_cloud_name
VITE_CLOUDINARY_UPLOAD_PRESET=your_unsigned_upload_preset
```

Перезапустите Vite / повторно разверните Vercel. Кнопка «Выбрать файл» загрузит фото на Cloudinary и подставит публичную ссылку. **После этого отдельно нажмите «Сохранить» в соответствующем редакторе**, чтобы URL попал в Firestore.

**Безопасность:** unsigned preset **публичный** и может использоваться посторонними, даже если кнопка есть только в админке. Ограничения форматов, размера на клиенте и медиа-параметров в Cloudinary уменьшают риск, но не исключают злоупотребления. Для серьёзной коммерческой эксплуатации потребуется подписанная загрузка на доверенном сервере (может потребовать другой инфраструктуры); не помещайте Cloudinary API Secret в frontend.

Изменение URL в галерее, карточках, Hero или акции должно сохраняться через существующий документ/коллекцию Firestore. Если выводит `permission-denied`, проверьте claim `admin: true` и опубликованные `firestore.rules`. Никакая новая Firestore-база не нужна.
